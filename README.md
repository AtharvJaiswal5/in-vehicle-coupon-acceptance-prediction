# Predicting In-Vehicle Coupon Acceptance

CA3 Predictive Analytics · Atharv Deepak Jaiswal · PRN **23070521023**

A reproducible KDD classification project predicting whether a survey participant says they would accept a coupon in a driving scenario. The target is survey intention, not observed redemption or sales.

## Results

Five-fold stratified grouped validation selected a **Random Forest**, using F1 as the primary criterion and ROC-AUC as a tie-breaker. The model uses 200 trees, unrestricted depth, and a minimum of two observations per leaf. The fixed decision threshold is 0.5.

| Held-out metric | Random Forest | Majority baseline |
|---|---:|---:|
| Accuracy | 0.7666 | 0.5686 |
| Precision | 0.7636 | 0.5686 |
| Recall | 0.8537 | 1.0000 |
| F1 | 0.8062 | 0.7250 |
| ROC-AUC | 0.8366 | 0.5000 |

The baseline always predicts acceptance, explaining its perfect recall but weak discrimination. Test confusion matrix: TN=713, FP=381, FN=211, TP=1,231. The test contains 2,536 rows; training contains 10,148. Random Forest F1 on the full training set is 0.9628 versus mean cross-validation F1 of 0.7914 (standard deviation 0.0068), indicating a substantial overfitting gap despite outperforming alternatives on validation.

| Algorithm | Validation F1 | Validation ROC-AUC |
|---|---:|---:|
| Majority baseline | 0.7248 | 0.5000 |
| Logistic Regression | 0.7337 | 0.7344 |
| Decision Tree | 0.7417 | 0.6764 |
| Random Forest | 0.7914 | 0.8176 |

The most influential variables by held-out permutation importance were coupon type, coffeehouse visit frequency, expiry, and bar visit frequency. Importance is association, not causation.

## Run the project

Use Python 3.12. From this project folder, create and activate a virtual environment, then install the requirements:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Open `coupon_acceptance.ipynb` in VS Code, Jupyter, or another compatible notebook editor; select the environment and **Restart Kernel and Run All**. Run with this folder as the working directory. No network access is needed after dependency installation because the CSV is included. Training regenerates results, figures and the saved model. The notebook uses a local CSV, not an absolute machine-specific path. If your editor needs JupyterLab, install it separately with `python -m pip install jupyterlab`.

The first run may take a few minutes, depending on the computer. Results use seed 42 and pinned packages; minor numerical differences may occur on different platforms. Only load the supplied model from this trusted project; joblib files are executable serialized objects.

## Method

1. Preserve all 12,684 observations, including 74 exact duplicate rows. Group identical input profiles (12,587 groups) before splitting to prevent profile overlap. Use the first shuffled five-fold stratified-group split as the approximately 80/20 holdout, and grouped five-fold validation inside training.
2. Explore training data only. Schema decisions on the training partition remove `car` (over 90% missing) and constant `toCoupon_GEQ5min`, leaving 23 original predictors. This schema screening precedes cross-validation; no holdout information determines it.
3. Fit categorical missing labels, one-hot encoding, numeric median imputation and numeric scaling within each training fold. Preserve age, income and visit-frequency bands as categorical. The pipeline ignores unseen categories and unused columns.
4. Compare majority baseline, Logistic Regression (`C`: 0.1, 1, 10), Decision Tree (depth: 3, 5, 10; minimum leaf: 5, 20), and Random Forest (200 trees; depth: 10 or unrestricted; minimum leaf: 2, 5).
5. Select using validation F1, then ROC-AUC; refit on all training rows. Evaluate the selected model and baseline once on holdout. Analyze errors and five-repeat permutation importance without retuning.

## Verified checks

The notebook ran completely in a fresh kernel. Assertions confirm zero predictor-profile overlap across holdout and validation partitions, target exclusion, successful handling of missing and unseen inputs, and identical predictions after model reload. All exported results derive from that execution. Hypothetical example predictions are labelled separately from observed data.

## Limitations

The data measures stated intentions in hypothetical scenarios. Respondent identifiers are unavailable: grouped identical profiles do not prove separation of people, and validation may remain optimistic. There is no external or temporal validation, probability calibration, fairness audit, or causal identification. Demographic inputs require review before practical use. Direction indicators are redundant and can divide importance. F1 treats error types symmetrically and is not a business profit measure. A future study should use respondent-level splitting, actual redemptions, calibrated probabilities and external data.
